# 调度策略本地实验

## 复现方式与限制

1. 将本地 `examples/1846_samples.zip` 解压到仓库外的临时目录。压缩包的 `sample_01/02` 是逐轮转录；本机调试工具需要顶层 `.in` 参数文件生成完整练习世界。
2. 执行 `python tests/generate_local_worlds.py <测例目录>`，得到 16 个固定种子和 8 个参数变体。参数基准见 `tests/local_world_base.in`。
3. 在 `csg_tpj_debug_player_windows_amd64.exe` 中设置交互题、时限 1 秒、内存 256 MB、`tpj_win.exe`、本地 `src/main.cpp`、可用的 MinGW `g++` 目录以及上述测例目录。运行后读取每组的对账错误、非法指令、利润和 CPU 时间。

本地评测程序不提供正式数据的隐藏利润目标。这里的 AC 只确认当前练习世界的协议、对账和指令合法，不能换算为 OJ 得分。选手 CPU 时间由 Windows 调试工具粗略统计。

## 策略变更

| 策略 | 16 个基准世界的结果 | 结论 |
|---|---|---|
| 上一提交：收益门槛 3.2、候选上限 128、带紧迫度加权 | 利润合计 18,812,994；14 组为正，最差 -377,451 | 低价值工作流的费用仍过高 |
| 将已完成部分作业的工作流单独放宽准入 | 多组利润下降，出现更大亏损 | 撤回 |
| 收益门槛 4.5、候选上限 128 | 16 组全正，合计 26,464,732 | 继续试验门槛 |
| 收益门槛 5.0、候选上限 128、去除紧迫度加权 | 16 组全正，合计 27,603,860 | 候选评估仍可缩减 |
| **当前：收益门槛 5.0、候选上限 96、按预计收益/成本排序** | **16 组全正，合计 28,901,377** | 利润与本机耗时的较优组合 |
| 候选上限 80 | 16 组全正，合计 28,621,539 | 合计利润下降，撤回 |

“收益门槛 5.0”指某候选机器上，预计工作流收益至少为该作业预计费用与其他待完成作业最低预计费用之和的 5 倍。它是实测策略参数，不是题面规则。运行成本估计按已完成作业校准租户时长；候选机器评价包含当前网络距离与缓存状态。
