# 星环算力调度系统：SDD 规格与开发流程

> 基准：用户提供的 OJ 题面，C++17，1 秒、256 MB。规则冲突时以 OJ 最新题面为准。本文是开发执行手册；实际代码在 `src/main.cpp`。

## 1. 目标、验收与边界

程序在每个 tick 接收事件与对账题，先回答全部对账，再下达调度指令。单组通过需同时满足：对账全对、无非法指令、最终利润达到隐藏目标。利润没有可见的本地通关阈值，因此开发顺序固定为：**协议正确 → 状态和对账正确 → 指令合法 → 策略优化**。

交付物：可直接提交 OJ 的单文件 C++17 程序、可交互运行的测试、固定种子的本地评测记录、课程报告中的数据结构选择与 AI 使用记录。不得以样例中的固定指令作为唯一正确调度；样例后续答案取决于此前实际执行的指令。

当前状态：单文件程序已实现；小型交互契约测试和样例 1 首轮对账通过。用户后来提供了 `examples/1846_samples.zip`，其中有本地评测程序。八组固定种子的正式规模练习世界已全部达到零对账错误、零非法指令；本地评测不提供正式数据的利润目标，因此**尚未验证 OJ 分数**。

## 2. 不可变协议和事件顺序

每轮严格按以下顺序执行：

1. 读 `TICK t ne nq`，并读取 `ne` 个事件。`WF` 后的 `n` 行作业属于该事件，不增加 `ne`。
2. 按事件给出的顺序依次更新状态。`DONE`、`FAIL`、`UP` 等先于本轮对账生效。
3. 读取并回答 `nq` 道对账题，输出 `ANS a_1 ... a_nq`；`nq=0` 时输出 `ANS`。
4. 决定本轮指令，并在本地按输出顺序逐条应用。输出 `END` 后立即刷新。
5. 第 `T` 轮输出完毕立即退出。

作业 `s` 启动、`r` 释放时，运行费为 `cpu × p_dc × (r-s)`。`BILL` 在 tick `t` 的答案包括当前仍运行作业截至 `t` 的运行费，且不包括本轮尚未执行的指令。最终利润另将第 `T` 轮仍运行的作业计费至 `T+1`。任何真实时长只由 `DONE` 事件揭示，不得用估计时长自行发出完成事件。

### 状态转移表

| 输入或指令 | 必须更新的状态 | 容易错的边界 |
|---|---|---|
| `DONE j` | 结算运行费、释放机器和祖先配额、记录输出机架、标记完成、递减后继未完成前驱数 | 完成先于本轮对账；仅这时后继才就绪 |
| `FAIL x` | 结算并中断该机所有运行作业、释放资源、标记机器故障、清空机器缓存 | 机架缓存保留；作业可重试 |
| `UP x` | 机器恢复、机器缓存为空 | 不自动恢复此前作业 |
| `DCDOWN/DCUP`、`LDOWN/LUP` | 改变网络可用性，使最短路缓存失效 | 机房停电不等于机器 `FAIL` |
| `QUOTA/UNDO` | 更新当前配额；`QUOTA` 压入旧值，`UNDO` 后进先出恢复 | 配额可以低于已占用量 |
| `LOG` | 只按给定的 `b` 个比特解码并更新机器告警窗口 | 十六进制最后的补零位无效 |
| `WF` | 建立工作流、作业、前驱和后继关系 | 外部 ID 是 9 位整数；前驱已在同一工作流中列出 |
| `RUN` | 先验证，再计传输和镜像拉取、修改两级缓存、增加费用和资源占用 | 多条指令顺序执行；准备期间也占资源和运行费 |
| `KILL` | 结算运行费并释放资源，作业回到待运行 | 已发生费用不退；缓存保留 |
| `DROP` | 标记工作流放弃 | 已完成或仍有运行作业时非法；既有费用不退 |

代码目前只输出 `RUN`，不主动输出 `KILL/DROP`；事件状态机仍支持由故障造成的重试。以后加入新的指令时，须先补对应的逐条合法性测试。

## 3. 数据结构和可检查的模块契约

| 模块 | 数据结构 | 不变量与查询 |
|---|---|---|
| ID 与 DAG | `unordered_map<外部 ID, 连续下标>`、作业数组、前驱/后继邻接表；每个工作流保存输入拓扑顺序 | 未完成前驱数为零且待运行，才可能 `RUN` |
| 租户树 | 父节点数组、配额、子树 CPU 占用；撤销栈 | `HEAD(o)` 为 `o` 到根各节点 `quota-used` 最小值；每次启动/释放沿祖先链更新 |
| 账单 | 每个祖先维护已结算费用 `settled`、当前运行费率 `rate`、截距 `intercept` | `BILL(o,t)=settled[o]+t×rate[o]+intercept[o]`；启动时 `rate+=cpu×p, intercept-=rate_delta×t`，释放时反向更新并将 `(t-s)×rate_delta` 结算 |
| 动态网络 | 邻接表、链路与机房状态、拓扑版本、按机架源点缓存 Dijkstra 距离 | `ROUTE(a,b)` 中任一端节点停电则为 `-1`；同节点且正常为 `0`；任何网络状态变化均使旧距离失效 |
| 两级镜像 | 每机器和每机架独立的 LRU 双向链表、层索引、已用容量 | 每层按镜像底层到顶层处理；机器命中只移动机器 LRU；机架命中移动机架 LRU；缺失时先插机架再插机器；每次插入后逐层淘汰 |
| 日志告警 | `(权重, 编号)` 小根堆建 Huffman 树；Aho–Corasick 自动机；每机器按 tick 聚合的队列 | 相同权重取小编号为左子树；`_` 中断模式匹配；重叠和重复模式均计分；窗口保留 `[t-W+1,t]` |
| `SLACK` | 在未完成作业诱导子图上正向计算 `ES`，反向计算 `TL`；按工作流完成数缓存 | `CP-ES(j)-TL(j)`；运行中作业仍用完整估计时长；`RUN/FAIL` 不改变未完成子图，`DONE` 会使缓存失效 |

### 关键判定

`RUN j x` 的独立合法性检查必须同时覆盖：作业待运行且工作流未放弃、前驱全完成、机器正常且 CPU/内存充足、租户到根每层配额足够，以及每份异机架输入可达。同机架输入不传输；即使该机架节点因机房停电而不能用于 `ROUTE`，这份同机架输入仍不需要路由。

传输时间对各份输入取最大值，传输费逐份求和。镜像拉取时间为两级拉取时间之和，准备时间为传输时间与拉取时间的最大值。只有仓库拉取量收取 `U_reg` 费用；已发生的传输、拉取和运行费都不可退还。大于缓存容量的层可能插入后立即淘汰，但该次拉取仍发生。

## 4. 分阶段实现与退出门槛

1. **建立仓库和题面基线**：记录目标仓库 SSH 地址、OJ 编译标准、样例包和本地评测程序版本。保持 OJ 提交入口为单个 `src/main.cpp`。完成条件：本地编译命令和版本信息可复现。
2. **交互骨架**：解析初始化、`TICK`、事件和问题；每轮输出正确数量的答案、`END` 并刷新。完成条件：以管道逐轮发送输入时不会等待后续 tick 才输出。
3. **确定性模块**：依次完成 DAG/资源、配额/账单、路由、缓存、日志、`SLACK`，每个模块写独立小场景。完成条件：状态不变量和七类对账均有覆盖。
4. **本地评测闭环**：先运行自建交互场景，再用样例包中的调试工具和顶层 `.in` 参数文件生成正式规模练习世界，记录第一处对账错误、非法指令、利润构成和耗时。样例包的 `sample_01/02` 是逐轮转录，不能直接当作调试工具的顶层 `.in` 参数文件；样例 1 首轮已纳入交互测试。完成条件：现有测试全绿，练习世界零对账错误、零非法指令；不把本地 AC 等同于 OJ 达到隐藏利润目标。
5. **保守调度基线**：只对已就绪作业估计经济性和可完成性，逐条验证合法再 `RUN`；每轮至多重点评估 128 个候选。完成条件：同 tick 多次 `RUN` 后资源和配额仍正确。
6. **逐因素优化**：分别试验估计时长校准、价值/成本排序、关键路径紧迫度、缓存与数据位置、机房单价及故障预警。一次只改一个因素，固定随机种子比较完成数、利润四项构成、耗时和非法率。无稳定收益的改动回退。
7. **提交与报告**：检查 1 秒和 256 MB 限制，保留验证记录，按里程碑谨慎使用 10 次 OJ 提交机会。每次记录 Git 提交号、OJ 分数及错误类型；只在有明确改动与验证证据时再次提交。报告写真实的数据结构取舍、验证证据、策略迭代和 AI 工具使用情况，与提交代码一致。

## 5. 测试清单与易错情况

- **交互**：`nq=0` 也输出 `ANS`；`WF` 作业行不算额外事件；本轮 `ANS` 使用事件后、指令前状态；每轮刷新；第 `T` 轮后退出。
- **生命周期**：同 tick 的 `DONE` 与 `FAIL` 按给定顺序处理；故障中断多个作业；`UP` 后机器缓存为空；重试的准备费和运行费重新计算。
- **配额和费用**：配额降至已用量以下；连续 `QUOTA` 后 `UNDO k`；父子租户同时查询；启动 tick、完成 tick、最后 tick 的计费边界。
- **网络**：同机架、同网络节点、断链、机房停电、恢复、重复 `ROUTE`；网络变化后不能复用旧距离。
- **缓存**：共享层、重复层、恰好装满、超容量层、机器命中、机架命中、仓库拉取、故障与修复后的两级缓存。
- **日志**：Huffman 相同频数的编号裁决、补零位、`_` 分隔、重复模式、重叠模式、窗口进入与过期。
- **DAG**：链、分叉、汇合；前驱完成前不能启动；运行中作业的 `SLACK` 不扣除已运行时间；工作流重复查询后发生 `DONE`。
- **策略**：无可用机器、无可达输入、资源或祖先配额不足、只剩仿真末尾 tick、候选数超限；所有跳过均不得造成非法指令。

`tests/test_protocol.py` 已检查管道刷新、动态 `BILL/HEAD/CACHE/RCACHE`、断链与停电后的 `ROUTE`、配额撤销、Huffman 解码后的 `ALARM`、`SLACK` 以及题面样例 1 首轮对账。`tests/generate_stress.py` 生成协议与性能压力输入，不生成 OJ 等价世界。样例包本地评测程序可检验完整练习世界的对账与指令，并给出利润构成；取得 OJ 分数后应先定位是协议/对账/合法性还是利润问题，再决定下一次修改。

## 6. 策略基线与实验记录格式

当前策略按工作流预计收益与剩余估计成本排序，给每轮前 128 个待运行作业寻找合法机器；机器评分计入估计运行费、传输费、仓库拉取费和准备延迟。工作流准入使用可运行机器上的计算费及外部输入传输费估计，已完成作业用于校准租户的真实时长偏差。实际选择机器后，再比较预计收益与该机器费用加剩余作业费用；当前保留 3.2 倍收益余量。它不能预知真实完成时间或故障，仅在预计可于仿真结束前完成的候选上 `RUN`。本地练习世界的调参结果不证明正式数据的隐藏利润目标已达成。

## 7. Git 和报告流程

本地仓库使用 `main` 分支，`origin` 为 `git@github.com:Cool-11/Computing-Power-Scheduling-System.git`。每个通过验证的阶段单独提交；提交前运行测试并检查差异，避免把评测二进制、随机生成的大文件或个人凭据加入仓库。远端推送前确认分支与文件范围。课程报告按学校模板填写，引用本仓库真实的结构选择、实验与错误修复记录；初版规格、代码和测试由 AI 辅助生成，使用范围需在报告中如实说明，最终提交者应逐模块理解、复核并独立完成后续策略实验。
